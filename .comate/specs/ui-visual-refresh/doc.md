# 前端界面视觉优化方案

## 一、现状问题

从你截图的 C 端聊天页和现有样式代码看，功能是完整的，问题集中在视觉层：

1. **配色缺乏层次。** 深色侧栏 `#1e293b` 与主区 `#f8fafc` 直接硬切，中间没有过渡；主色只有单一蓝 `#2563eb`，医疗产品应有的清洁感和信任感没有体现出来。
2. **空状态单薄。** `ChatView.vue:51-83` 的空态是一个灰色描边心形图标 + 两行说明 + 三个小圆角按钮，图标 `stroke-width="1"` 过细在大尺寸下显得虚，示例问题按钮样式偏弱，不像可点的入口。
3. **消息气泡对比不足。** 用户消息是蓝底白字圆角气泡，AI 回复是纯文本贴在页面上，两者视觉重量不对等，长对话时难以快速扫读。AI 头像是 8×8 的浅蓝圆底「AI」文字，略显简陋。
4. **留白与节奏偏紧。** 侧栏项 `py-2.5`、消息 `py-4`、Header 高度 `h-14`，整体密度偏高；`max-w-4xl` 在宽屏下文本行偏长，阅读舒适度一般。
5. **缺少细节质感。** 全站几乎没有阴影层级、没有 focus ring 规范、hover 过渡只有颜色变化；按钮和输入框缺少统一的圆角与投影语言。
6. **反馈与免责区样式割裂。** 免责声明用琥珀色告警块（`ChatMessage.vue:570`），反馈区是裸文字加小按钮，两块紧邻但风格不统一。
7. **两端视觉未区分。** O 端只把侧栏底色从 `slate-800` 换成 `slate-900`，主区完全一致，缺少「这是运营后台」的辨识度。

## 二、设计目标

- 建立一套可复用的设计令牌（颜色、圆角、阴影、间距），避免继续散落硬编码。
- C 端偏「医疗清洁感」：留白充足、圆角柔和、主色偏医疗蓝绿。
- O 端偏「控制台感」：信息密度更高、色调更冷、强调数据区块。
- 不改变任何交互逻辑、路由与数据流，只动视觉层。
- 不引入新的 UI 框架或组件库，继续用 Tailwind + 现有结构，控制改动面。

## 三、方案

### 1. 设计令牌统一（`style.css`）

扩展 `:root`，补齐语义色、层级阴影与圆角：

```css
:root {
  /* 主色：医疗蓝，带完整梯度用于 hover / active / 浅底 */
  --brand-50: #eff6ff;
  --brand-100: #dbeafe;
  --brand-500: #3b82f6;
  --brand-600: #2563eb;
  --brand-700: #1d4ed8;

  /* 辅助色：用于健康 / 提示 / 风险 */
  --accent-teal: #0d9488;
  --color-success: #16a34a;
  --color-warning: #f59e0b;
  --color-danger: #dc2626;

  /* 中性层级：背景 / 卡片 / 分割线 */
  --surface-page: #f6f8fb;
  --surface-card: #ffffff;
  --surface-muted: #f1f5f9;
  --border-subtle: #e6ebf2;

  /* 阴影三档 */
  --shadow-sm: 0 1px 2px rgba(15, 23, 42, 0.04);
  --shadow-md: 0 4px 12px rgba(15, 23, 42, 0.06);
  --shadow-lg: 0 12px 32px rgba(15, 23, 42, 0.10);

  /* 圆角 */
  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 16px;
}
```

同时补统一的 focus ring 与滚动条样式，把现在只在个别组件里出现的 `focus:ring-2 focus:ring-blue-500` 提炼成一致规则。

### 2. C 端侧栏

- 底色改为带轻微渐变的深蓝（`slate-900 → slate-800` 纵向），与主区之间加一条极淡的高光边，消除硬切感。
- Logo 区加圆角方块 + 品牌渐变，副标题字号与字重下调，减少与主标题的竞争。
- 导航项圆角改 `--radius-md`，选中态用「浅色背景 + 左侧 2px 主色指示条」替代纯背景色块，层次更清楚。
- 「新建会话」按钮改为主色渐变 + `--shadow-sm`，hover 轻微上浮。
- 会话列表项增加 hover 背景与 1px 分隔感，时间戳与标题建立字号差；删除按钮保持 hover 出现。
- 底部账号块改为卡片式（浅色半透明底 + 圆角），管理员标识做成小 pill 徽章。

### 3. C 端聊天区

**空状态重做：**

- 图标换成带浅色圆形底盘的医疗图标（听诊器/十字），`stroke-width` 提到 1.5，尺寸与底盘配比协调。
- 标题字号提到 `text-2xl`，副标题收敛成一行，去掉「多智能体 Swarm 架构」这类技术表述（患者视角无意义）。
- 示例问题改成三张等宽卡片：小图标 + 问题文本，hover 时边框变主色、轻微上浮，明确可点。

**消息气泡：**

- 用户消息保留蓝底，改为主色渐变 + `--shadow-sm`，圆角统一 `--radius-lg`。
- AI 回复放进白色卡片（`--surface-card` + `--border-subtle` + `--shadow-sm`），与用户气泡形成对称的视觉重量。
- AI 头像换成品牌渐变圆底 + 简洁图标，尺寸提到 9×9。
- 消息间距从 `py-4` 提到 `py-5`，正文容器宽度从 `max-w-4xl` 收到 `max-w-3xl`，行长更适合阅读。

**免责声明与反馈：**

- 免责声明从「告警块」降级为「低干扰提示条」：浅灰底 + 左侧细边 + 小号图标，保留完整文案（医疗安全要求不能弱化，只调整视觉强度）。
- 反馈区做成一行胶囊按钮，选中态用主色浅底 + 主色文字；展开的原因勾选区放入浅色卡片，与免责条统一圆角。

**输入区：**

- 外层加白色卡片 + `--shadow-md`，与消息区形成浮起关系。
- 输入框 focus 时显示主色 ring；发送按钮改主色渐变圆形，禁用态降饱和而非纯灰。
- 图片上传按钮与发送按钮尺寸对齐，图标粗细统一。

### 4. O 端视觉区分

- 侧栏保持更冷的深色，主色点缀用 indigo，与 C 端蓝形成区分。
- 主区背景略深于 C 端（`#f1f5f9` 级），强调这是数据密集界面。
- Header 增加端标识 pill（已有 `portalLabel` 文本，改为徽章样式）。
- 仪表盘卡片统一 `--radius-md` + `--shadow-sm` + 悬停 `--shadow-md`，数字用等宽数字字体（`font-variant-numeric: tabular-nums`）避免跳动。

### 5. Header 与登录页

- Header 高度 `h-14 → h-16`，标题字重下调一档，右侧放端标识徽章。
- 登录页加品牌渐变背景（极淡）、卡片阴影提到 `--shadow-lg`，输入框与按钮沿用新令牌；免密登录风险提示保留，改为低干扰样式。

## 四、受影响文件

仅视觉层，不动逻辑：

- `frontend/src/style.css`：设计令牌、focus ring、滚动条、markdown 与引用样式微调
- `frontend/src/components/layout/CSidebar.vue`：侧栏视觉
- `frontend/src/components/layout/OSidebar.vue`：O 端侧栏视觉
- `frontend/src/components/layout/AppHeader.vue`：高度与端徽章
- `frontend/src/components/layout/CLayout.vue`、`OLayout.vue`：背景层级
- `frontend/src/views/ChatView.vue`：空状态与容器宽度
- `frontend/src/components/chat/ChatMessage.vue`：气泡、头像、免责条、反馈区
- `frontend/src/components/chat/ChatInput.vue`：输入卡片与按钮
- `frontend/src/views/LoginView.vue`：登录卡片
- `frontend/src/views/DashboardView.vue`：统计卡片样式

不修改：路由、store、API、类型定义、事件聚合与打字机逻辑。

## 五、边界与约束

- 医疗免责声明文案一字不改，只调整视觉强度，确保仍清晰可读（对比度不低于 WCAG AA）。
- 所有可交互元素保留可见 focus 状态，满足键盘可达性。
- 不删除任何现有功能入口；改动后需确认新建会话、会话删除、图片上传、问卷提交、反馈提交、引用 Popover 全部正常。
- 流式输出期间的「思考中」动画、ThinkingBlock 展开态在 O 端保持可用。
- 窄屏（≤768px）下侧栏与消息区不出现横向滚动或遮挡。
- 不新增运行时依赖，构建产物体积不应显著增加。

## 六、预期结果

1. 全站有统一的颜色、圆角、阴影语言，后续改动不再散落硬编码。
2. C 端聊天页空状态与消息区明显更清晰、更有医疗产品质感。
3. O 端与 C 端一眼可辨。
4. 功能零回归，测试与构建全部通过。

## 七、需要你确认

1. **视觉风格倾向**：
   - A. 保持现有蓝色主色，只做层次与留白优化（改动最小，本方案默认）
   - B. 主色调整为医疗蓝绿（teal 系），观感更「医疗」但品牌色变化明显
2. **改动范围**：
   - A. 全站（C 端 + O 端 + 登录页，本方案默认）
   - B. 只做 C 端聊天相关页面，O 端后续再说
3. **深色模式**：
   - A. 本期不做（本方案默认）
   - B. 一并加入深色模式支持（工作量显著增加）
4. **侧栏形态**：
   - A. 保持深色侧栏（本方案默认）
   - B. 改为浅色侧栏，整体更轻盈
